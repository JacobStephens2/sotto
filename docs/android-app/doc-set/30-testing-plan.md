# Testing / Validation Plan

## Pyramid

**1. Pure-logic unit tests (most coverage, JVM, fast)**
- The ported `clean_markdown()` and `chunk()` against the **shared test-vector
  file**: a JSON corpus generated by running the Python originals in the sotto
  server repo over a fixed set of inputs (headings, tables, links, §-citations,
  unicode, the encyclical's hardest paragraphs, pathological whitespace).
  Generation script lives server-side; the JSON is committed in both repos.
  Any intentional pipeline change regenerates vectors in the server repo first -
  the server is the reference implementation.
- Title derivation, estimator median math, state-machine transitions
  (every edge in 11-data-model.md, including illegal-transition rejection).

**2. Instrumented tests (Room + engine, emulator x86_64 debug variant)**
- Resume correctness: kill the process mid-narration at randomized chunk
  boundaries; assert byte-identical output versus an uninterrupted run (the
  server proved this property; the app must too).
- Room migrations from schema v1 forward, orphan-sweep behavior.
- Synthesis runs with a tiny stub model in CI (real Kokoro is too heavy for
  emulator CI); real-model correctness is a device-matrix item.

**3. On-device tests (manual matrix + scripted where possible)**
- Full PRD acceptance criteria, S1-S5.
- The SPIKE-001 measurements re-run before each release (RTF, battery/hour,
  thermal) and recorded in the release notes - performance is a feature here.

## Device / OS matrix

| Device | Role |
|---|---|
| Pixel-6-class (owned) | Floor for performance gates (N2, N3) |
| One mid-range arm64 (e.g. Moto G-series) | Reality check below the floor |
| Emulator x86_64, API 29 | minSdk correctness only, never performance |
| Emulator x86_64, latest API | Behavior-change canary (FGS/notification policy) |

## Merge criteria

- JVM + instrumented suites green in CI.
- Manifest check passes: no INTERNET/ACCESS_NETWORK_STATE in merged manifest
  (ADR-004) - this is a *test*, not a review item.
- Test-vector file hash matches the server repo's published hash (drift alarm).
- No new lint errors; ktlint clean (40-code-style.md).

## Release criteria (adds to merge criteria)

- PRD acceptance pass on both physical devices.
- A forced-kill resume test on a real >10,000-word document.
- One full release-pipeline dry run (signed APK installs and upgrades over the
  previous release without data loss).
